# round22 04: SMC 60..65 (+ 28/69/6a/26 control set)

source: `bl33_audit.py smc` census (15 opcode-exact `smc #0` sites) + per-site
disasm. X1/X2/X3 are NEVER set up at any 60..65 site: the payload travels in
`[[0x37fbde60]]`, the response in `[[0x37fbde58]]`. all six go through the
shared stub `0x37e8bba0` (`smc #0; ret`).

## 4.1 table (code-exact)

```text
SMC        | caller (low fn) | operation (DTB name)   | C1 (IN stage)              | C2 (OUT parse)              | BLOCK | argv influence                    | reachable from run_command
0x82000060 | 0x37e8be98      | SECURITY_KEY_QUERY     | [IN+0]=namelen + name      | [OUT+0] word -> *caller     | no    | name only, via fastboot shim only  | NO (fastboot-only, 02.3)
0x82000061 | 0x37e8bdc8      | SECURITY_KEY_READ      | [IN+0]=namelen,[IN+4]=hint + name | [OUT+0]=len, [OUT+4..]=blob -> caller buf + *len | no | keyman read: name+C1, dest addr+C2 | YES (keyman read, 02.2)
0x82000062 | 0x37e8bd10      | SECURITY_KEY_WRITE     | [IN+0]=namelen,[IN+4]=datalen,[IN+8]=flags + name + data | none (return code only) | no (backend copy aside, see below) | keyman write: name+data+len | YES (keyman write, 02.1)
0x82000063 | 0x37e8bfe0      | SECURITY_KEY_TELL      | [IN+0]=namelen + name      | [OUT+0] word -> *caller     | no    | name only, via fastboot shim only  | NO (fastboot-only, 02.5)
0x82000064 | 0x37e8c084      | SECURITY_KEY_VERIFY    | [IN+0]=namelen + name      | [OUT+0..0x20) 0x20-B memcpy | no    | name only, via table only        | NO (table-only, 02.6)
0x82000065 | 0x37e8bf3c      | SECURITY_KEY_STATUS    | [IN+0]=namelen + name      | [OUT+0] word -> *caller     | no    | name only, via table only        | NO (table-only, 02.4)
```

arguments: X0 = id (mov `x0,#id` + `movk x0,#0x8200,lsl#16` at each site);
X1/X2/X3 = caller residue (never set). return: X0 status; `cbnz`-gated parse
in every reader; write ignores the stub return and uses its epilogue code.
C1/C2 usage is as round21 states; BLOCK is never touched on these six paths
(no load of `[0x37fbde68]` in any of them).

## 4.2 read/write/query/status/tell/verify split (no name-based claims)

- storage write (0x62): caller `amlkey_write`; data returned: none (status
  only); dest: BL31; normal-world exposure: none on return; command exposure:
  YES (`keyman write`). do NOT call it "key read useful" or similar.
- storage read (0x61): caller `amlkey_read`; data: `len + blob` (shape
  CONFIRMED, plaintext-vs-cipher UNKNOWN); dest: caller RAM; exposure:
  argv-chosen RAM via `keyman read` (YES), USB response via fastboot shim
  (YES, separate path)..
- storage query (0x60): caller `amlkey_isexsit`; data: one status word;
  NOT key material; command exposure: NO via `run_command`.
- storage status (0x65): caller `amlkey_get_attr`; data: one attr word; NO.
- storage tell (0x63): caller `amlkey_size`; data: one size word; NO.
- storage verify (0x64): caller table path; data: 0x20-B blob compared
  locally; NO via `run_command`.

the public SMC names (`SECURITY_KEY_*`) come from `bl31_apis.h` / DTB props;
the verdicts above come from callers + dataflow, not from the names.

## 4.3 control SMCs (contrast, all scalar, no buffers)

- `0x82000028 SET_STORAGE_INFO`, wrapper `0x37e8c138`
  (`mov w1,w0; mov x0,#0x28; movk; smc; ret`). sole `bl` caller `0x37e90614`
  in `0x37e904ac` (boot/state machine): `ldr w0,[x19,#0xec]`, `cmp #1`,
  taken path does `str w2=#2,[0x37f60878]` (store backend selector = 2) then
  `bl` with X1 = 1. return value ignored for control flow (boot continues at
  `0x37e90618` regardless). touches NO share slot, NO C1/C2/BLOCK. section 9
  details; verdict: init/enable/mode selector for the store backend, NOT a
  staging consumer. REFUTED for buffer use.
- `0x82000069 NOTIFY_EX`, wrapper `0x37e8bcfc`
  (`mov w2,w1; mov w1,w0; x0=0x69; b stub`). sole caller `0x37e8c2a0` in
  `amlkey_init-ish 0x37e8c1dc`. scalar, no sharemem.
- `0x8200006a SET_ENCTYPE`, wrapper `0x37e8c14c`
  (`mov w1,w0; x0=0x6a; bl stub`). sole caller `0x37e8c264` in `0x37e8c1dc`.
  scalar, no sharemem. the enctype switch exists but BL33 never branches on
  it around OUT (round21 03): do not claim OUT content from it.
- `0x82000026 MESSAGE_BASE`: zero setup sites in the whole image (movz/movk
  + smc census) and no DTB `storage_message` prop. UNUSED. not part of any
  path.
- `0x82000066/67/68/6b/6c` (notify/list/remove/get_enctype/version): zero
  setup sites. never issued. DTB lists `0x6a/0x6b/0x6c` props but code only
  issues `0x6a` (once) and never `0x6b/0x6c`.

## 4.4 BLOCK on the op path

none. BLOCK (`[[0x37fbde68]]` + size `[0x37fbde48]`) is loaded only by
`getbuffer 0x37e8bc84` (two call sites, both in `0x37e8c1dc`) and handed to
`store_key_read 0x37e350e8` / `store_key_write 0x37e35170` behind the
`[0x37f60878]` selector. the `amlkey_write` tail also passes a stale copy
(`0x37f5fd68` struct) to `store_key_write`. none of this stages request bytes
or parses responses; it is the eMMC-side backend mirror of the SMC op, with
one bounded `memset(base,?,0x100)` on an error leg. capacity `0x40000` is a
BL31 report refreshed per `getbuffer`, max BL33-demonstrated use `0x100`.
