## acquisition attempt 1 (session 1, stage 16 confirmed)

- READ_MEM 0x02 @ 0x05300000, 64 B -> USBError [Errno 5] Input/Output Error.
- device 1b8e:c003 disconnected mid-transfer (dmesg: `USB disconnect,
  device number 8`), then rebooted to Android 2717:4e40 (device number 9).
  C1 reads in the same session (0x02 + full 64K mread) were healthy, so the
  only new variable was the address.

## recovery (read-only, no ADB reads, no writes)

- `adb reboot bootloader`: device left ADB, no fastboot appeared.
- per operator correction (`reboot fastboot, nao bootloader`):
  `adb reboot fastboot` -> 18d1:0d02 back.
- `fastboot oem update 5000` (sanctioned entry only) -> 1b8e:c003 back.
- identify: raw `00 07 00 10`, version 0.7, stage 16, exit 0.

## acquisition attempt 2 (session 2, stage 16 confirmed)

- mread (0x34+0x33) @ 0x05300000, 0x10000: bulkcmd armed, upload header
  returned nonzero, then bulk-IN died -> USBError [Errno 19] No such device.
- dmesg: `USB disconnect, device number 12` at the mread. device off-bus.

## result

C2 = UNREADABLE from TPL/BL33 Optimus. two sessions, two different request
paths (0x02 control-IN; 0x34+0x33 bulk), same address, same outcome: the
gadget faults and the stick drops off USB. deterministic, not flakiness.

no c2 bin exists (nothing acquired; no fake bytes written). sha256 n/a.
classification: UNKNOWN (not DATA_ONLY — no bytes to classify).

reading: secos status=disabled plausibly means the region is unmapped in the
TPL view, so the memcpy faults (data abort in gadget -> disconnect). or a
secure-read fault. either way TPL cannot serve 0x05300000. recorded as
mechanism hypothesis, not finding.

per brief s4: this absence proves nothing about historical BL31. C2 stays
UNKNOWN, with a concrete protocol failure instead of an empty gate.
